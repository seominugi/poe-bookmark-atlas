🔴 **영문 원본 경로 — 제보로 결과가 나왔다 (2026-08-18, 원인 해소 · 남은 확인 있음)**

- **해결**: pathofexile 을 **기본 `host_permissions`** 로 승격(`6d81db1`). 설치만 하면 영문 경로를 탄다.
- ⏳ **여전히 남은 확인**: 권한이 켜진 상태에서 영문 원본이 **값을 맞게 내는지**는 아직 미검증이다. 위 제보는 폴백 경로의 버그였지 영문 경로의 검증이 아니었다.
- 실패(권한 없음·오프라인·매물 팔림)는 기존 번역으로 폴백한다. **조회가 성공했는데 결과가 틀리는 경우는 폴백이 못 잡는다** — 그래서 위 ⏳ 가 남아 있다.
- 개발 환경에서 끝내 확인 못 한 이유 ①: 원격 조종 탭이 **OS 창 포커스를 못 잡아**(`document.hasFocus() === false`) 클립보드 쓰기가 `NotAllowedError` 로 막혔다. `window.focus()` 로도 안 된다. **사람이 직접 눌러야 확인된다.**
- 이유 ② (2026-08-18 추가): 에이전트 브라우저에는 **거래소 로그인 세션이 없어** 페이지 진입 자체가 카카오 로그인으로 막힌다. 단 **API 는 열려 있다** — `www.pathofexile.com/api/trade/*` 는 한국 IP 에서 인증 없이 200 이라, 매물 JSON 을 받아 원인을 규명하는 것까지는 에이전트가 할 수 있다(이번에 그렇게 했다). ⚠ CORS 는 닫혀 있고 curl 은 Cloudflare 403 이다 — **브라우저 안에서** 부를 것.
- 확인 방법(10초): 거래소에서 PoB 클릭 → 배지가 `영문 원본 ✓` 인지(`✓` 면 폴백), 붙여넣은 값이 맞는지.
- 이상이 있으면 되돌리기는 쉽다 — `pobCopy` 에서 `fetchEnItem` 호출만 빼면 기존 번역 경로로 완전히 복귀한다(맵을 안 지웠기 때문).

**② PoB 복사를 영문 거래소 원본으로 (`ff6205f`)** — 번역 대신 **같은 매물 id 를 영문 거래소에서 받는다**.
- 근거(2026-08-17 실측): PoE 는 단일 서버라 카카오 매물 id 를 `www.pathofexile.com/api/trade/fetch/<id>` 에 넣으면 **인증 없이 200**. `?query=` 도 불필요. 스탯·베이스 타입·**유니크 이름**까지 영문. PoE2 동일.
- 경로: 영문 거래소면 same-origin / 카카오면 서비스 워커 `ba-fetch-en` 대행. **2026-08-18부터 기본 권한**이라 별도 허용이 필요 없다(사용자가 크롬에서 사이트 접근을 내린 경우만 예외).
- `buildPobText(…, { en: true, itemClass })` — 설명을 그대로 쓰고 번역을 건너뛴다. 미변환·의심 항목이 0 이 된다. 조립 헬퍼는 이미 언어 중립(`/품질|Quality/`)이라 재사용했다 — **별도 빌더를 만들면 섹션 순서·접미 규칙이 두 벌이 된다.**
- ⚠ 영문 응답에 **Item Class 가 없다** → KR 아이템의 `baseMap` 으로만 구한다.
- ⚠ **기존 번역 경로는 지우지 않았다.** 권한 미허용·오프라인·매물 판매됨이면 폴백한다. 폴백이 거의 안 쓰이는 게 확인되면 그때 맵 **약 2.5MB + 로직 298줄**을 걷어낸다. 지금 지우면 권한 미허용 사용자의 PoB 가 통째로 죽는다.
- 배지로 경로를 구분할 수 있다 — `영문 원본 ✓`(새 경로) vs `✓`(폴백).
- ⚠ **권한이 없으면 조용히 폴백**해서 사용자가 더 나은 경로의 존재를 모른다 → PoB 를 눌렀을 때 `no-permission` 이면 **세션당 한 번** 토스트로 팝업 안내를 띄운다. 매번 띄우면 반복 동작이라 잔소리가 된다. 콘텐츠 스크립트에서는 `chrome.permissions` 를 쓸 수 없어(확장 페이지의 사용자 제스처 전용) 직접 요청하지 않고 팝업으로 보낸다.
- ⚠ 서비스 워커의 `reason` 과 콘텐츠 스크립트의 분기가 **문자열로만** 이어져 있다 — 어긋나면 안내가 영영 안 뜨고 조용히 폴백만 한다. 소스 대조 테스트로 고정했다.

### 🔬 조사 결과 — PoB 번역을 통째로 없앨 수 있다 (2026-08-17 실측, 미착수)

사용자 제안: *"우리 번역 데이터 말고, 거래소 아이템 id 로 영문 거래소 데이터를 가져올 순 없나?"* → **전면적으로 가능하다.**

카카오에서 만든 **매물 id 를 영문 거래소 API 에 그대로** 넣으면 인증 없이 200 이 온다.

| 확인 | 결과 |
|---|---|
| `GET www.pathofexile.com/api/trade/fetch/<카카오 매물 id>` | **200, 인증 불필요** |
| 스탯 | `1초마다 생명력 13.8 재생` → `Regenerate 13.8 Life per second` |
| 베이스 | `보병 브리간딘` → `Infantry Brigandine` |
| **유니크 이름** | `종말의 발` → `Apocalypse Span` |
| PoE2 | 동일 동작 (`견목 타지` → `Hardwood Targe`) |
| `?query=` | **없어도 200** — 검색 id 불필요 |
| rate limit | `trade-fetch-request-limit` · IP `12:4:10,16:12:300,50:300:300,1000:21600:1800` (4초당 12회) |

없앨 수 있는 것: `pobStatMap`(1,487+577KB)·`pobBaseMap`(362KB)·`pobUniqueMap`(61KB)·`pobUniqueModMap`(78KB) = **약 2.5MB** + 번역 로직 298줄. 오늘 고친 855개 값 오류·변형 선택·미변환 제보가 전부 존재 이유를 잃는다.

⚠ **대가**: ① 카카오에서는 cross-origin 이라 **`www.pathofexile.com` 호스트 권한**이 필요하다(현재 optional — 필수로 올리면 기존 사용자 확장이 승인 대기로 꺼진다) ② 즉시 복사가 **네트워크 왕복**이 된다(실패·지연 가능) ③ 매물이 팔리면 영문 조회가 빈다.

**권장 설계**: 영문 조회를 1순위로 쓰고 **실패·권한 없음이면 지금의 번역 맵으로 폴백**. 그러면 대가가 전부 "느려지거나 예전 품질로 떨어질 뿐"이 된다. 폴백이 거의 안 쓰이는 게 확인되면 그때 맵을 지운다. **바로 지우면 권한 미허용 사용자의 PoB 가 통째로 죽는다.**

- **리다이렉트는 우리 탓이 아니다** — 한국 IP 에서 `www.pathofexile.com/trade/search/Standard` → `poe.kakaogames.com/login/kakao?redir=...` 로 서버가 보낸다. 우리 콘텐츠 스크립트가 **주입되지도 않은 상태**에서 일어났다. 다만 해외 IP 는 그 대상이 아닐 텐데도 같은 증상이었다면 **우리 팝업이 카카오를 하드코딩한 것**이 원인이었고 그건 고쳤다.

### 업데이트 노트 페이지 — 새 버전에 무엇이 바뀌었는지 알리기 (2026-08-18, 브랜치 `claude/folder-duplicate-deletion-bug-220309`)

**왜**: 스토어 설명은 **기존 사용자가 보지 않는다.** 알리지 않으면 만든 기능이 발견되지 않는다.

**언제 알리나 — 거래소를 열 때 토스트 (사용자 결정)**
자동 업데이트는 사용자가 모르는 사이 일어난다. 그 순간 창을 띄우면 **전체화면 PoE 의 포커스를 뺏을 수 있고**(확장은 게임 실행 여부를 알 수 없다) 거래 중이면 손해로 직결된다. 그래서 **거래소 페이지를 보고 있을 때 = 브라우저 앞에 있을 때**만 말을 건다.
- 토스트에 액션 2개: **`노트 보기`**(새 창) · **`더 이상 안 보기`**(닫기). 둘 중 하나를 누르기 전까지 **계속** 뜬다
- `toast(msg, action)` 를 **배열도 받도록** 확장했다(하위호환 — 기존 호출부 무변경)

**구성**
- `src/lib/updateNotes.js` — `UPDATE_NOTES` 데이터 + `cmpVersion`·`notesSince`·`hasUnseen`. **순수 함수라 테스트가 직접 검증**한다
  - `cmpVersion` 은 자리수별 숫자 비교다. 문자열 비교를 쓰면 `'0.9.10' < '0.9.2'` 가 되어 새 버전을 건너뛴다
  - `notesSince(seen, current)` 는 **`current` 이하만** 낸다 → 다음 릴리즈 노트를 미리 적어둬도 배포 전까지 새지 않는다
  - 자동 업데이트를 여러 번 건너뛸 수 있으므로 **누적** 표시한다
- `src/update/update.html`·`.css`·`.js` — 노트 창. 팝업(`popup.css`)의 자수정 글래스 언어를 따르되 **토큰을 공유하지 않는다**(팝업은 360px 고정, 여기는 창이라 폭 가정이 다르다)
- 서비스 워커 `ba-open-update` → **`chrome.tabs.create`** (2026-08-18 사용자 결정으로 창 → 탭 변경, `d4effe7`). 처음엔 팝업 창이었는데 크기가 고정이라 노트가 적으면 휑하고 창 관리를 사용자가 떠안았다. 탭의 '닫기'는 `tabs.getCurrent`→`tabs.remove` 다 — `window.close()` 는 스크립트가 연 창에서만 통한다
- `onInstalled(reason='install')` 에서 `updateNotesSeen` 을 현재 버전으로 초기화 — **신규 설치자에게는 지난 노트를 띄우지 않는다**(투어가 그 자리를 맡는다). `reason='update'` 는 건드리지 않아야 토스트가 뜬다
- 팝업에 **'업데이트 노트 보기'** 버튼(`?all=1` — 전체 이력). 토스트를 놓쳤을 때의 문
- `vite.config.js` 에 엔트리 추가 — `update.html` 은 manifest 가 참조하지 않아 crxjs 가 못 잡는다

**검증** (테스트 **521/521** · 빌드 통과 · dist 에 `src/update/update.html` 포함)
- 하네스에서 **실제로 동작 확인**: 토스트가 뜨고(버튼 2개) · `노트 보기` → `{type:'ba-open-update'}` 발신 · `더 이상 안 보기` → `updateNotesSeen='0.9.2'` 기록
- `test-harness/update.html` 신설 — 노트 창을 **실제 부트스트랩 그대로** 브라우저에서 연다(`?seen=` 로 빈 상태, `?all=1` 로 전체 이력). 마크업을 미리보기에서 다시 조립하지 않는 게 요점이다
- CSS·반응형 실측: 자수정 토큰 적용 · 420/768/1280 전부 가로 오버플로 0 · `max-width:620px` 동작 · 빈 상태 정상
- ⏳ **실제 새 창(`chrome.windows.create`)은 미검증** — 확장을 로드해야 확인된다

**⚠ 릴리즈할 때 반드시**: `UPDATE_NOTES` 맨 앞에 새 버전 항목을 추가한다. **manifest 버전만 올리고 노트를 안 적으면 아무것도 안 뜬다**(`notesSince` 가 current 이하만 내므로). 문구는 커밋 제목이 아니라 **사용자가 겪는 변화**로 쓴다.

### PoB 영문 복사 — 조용한 폴백 규명 + 영문 거래소 권한 승격 (2026-08-18, 브랜치 `claude/folder-duplicate-deletion-bug-220309`)

**제보**: *"pob 복사넣기 희망의 실타래 같은 반경 주얼 같은 건 적용이 안 되던데 안 되는 게 정상일까요?"* — 붙여넣은 텍스트에 `Radius: 변수`·`통로` 같은 한글이 섞여 있었고, 배지는 `복사됨 · 미변환 2`.

**원인은 두 층이었다.**

**층 1 — 영문 경로가 아예 안 타졌다.** `미변환 N` 배지는 **번역 폴백 경로에서만** 나온다(영문 경로는 무조건 `영문 원본 ✓`이고 missing 을 세지도 않는다, `content-main.js` pobCopy). 즉 버튼 이름은 'PoB 영문 복사'인데 `fetchEnItem` 이 실패해 조용히 번역본으로 떨어져 있었다. 원인은 `optional_host_permissions` 미허용.

**층 2 — 폴백 경로 자체의 결함 3종** (영문 원본 실물로 재현 확인).
거래소는 유니크의 **여러 줄 mod 를 한 덩어리**로 주고 stat id 를 하나만 붙인다:
```
description: "Passive Skills in Radius can be Allocated without being connected to your tree\n-19% to all Elemental Resistances\nPassage"
hash:        "stat.explicit.stat_2901986750"   ← '모든 원소 저항' id = 덩어리의 **2번째 줄**
```
그런데 `pobExport.withTrailingLines` 는 id 의 EN 템플릿을 **첫 줄로 간주**한다. 그래서:

| KR 덩어리 | 처리 | 출력 |
|---|---|---|
| 반경 내 패시브…할당 가능 | EN 템플릿이 이 자리를 차지 | **줄 통째로 유실** |
| 모든 원소 저항 -17% | `+#%` 템플릿에 `-17` 채움 | `+-17% …` (부호 겹침) |
| 〃 (rest 로 밀림) | `modMap` 재매칭 성공 | `-17% …` |
| 통로 | 사전에 없음 | `통로` (KR 잔존) |

제보의 4줄과 정확히 일치한다. `미변환 2` = `radius:변수` + `explicit:stat_2901986750 — 통로`.
`Radius: 변수` 는 별개로 `RADIUS_EN = { 작게:'Small', 대형:'Large' }` 에 `변수` 가 없어서다(영문 원본은 `Radius: Variable`).

**이번에 한 것 — 권한 승격 (사용자 결정)**
- `https://www.pathofexile.com/*` 를 `optional_host_permissions` → **`host_permissions`** 로 이동. `optional_host_permissions` 키 제거
- 팝업 버튼은 **평소 숨김**, 사용자가 크롬에서 사이트 접근을 내렸을 때만 '접근 다시 켜기'로 노출(`renderGlobalBtn`)
- `no-permission` 방어·안내 토스트는 **유지**(크롬은 기본 권한도 사용자가 내릴 수 있다). 문구를 새 상황에 맞게 수정
- ⚠ **릴리즈 시 반드시 안내**: 권한 확대라 크롬이 기존 설치본을 비활성화하고 1회 재승인을 요구한다

**오늘 실측한 사실 (CLAUDE.md 에도 반영)**
- 영문 거래소 **API 는 한국 IP 에서 인증 없이 200** — `data/leagues`·`search`(POST)·`fetch` 전부. 리다이렉트되는 건 **HTML 페이지 경로뿐**이다
- ⚠ **CORS 는 닫혀 있다** — 다른 origin 에서 부르면 `Failed to fetch`. 서비스 워커 + host permission 이 **유일한 경로**(그래서 권한 승격 외에 방법이 없었다)
- curl 은 Cloudflare 가 403 — 검증은 브라우저에서 할 것

**검증**: 테스트 508/508 · `npm run build` 통과 · `dist/manifest.json` 에서 `host_permissions` 3개·`optional_host_permissions` 없음 확인.
⏳ 라이브 미검증 — 거래소 로그인 세션이 필요해 실제 PoB 복사 재현은 못 했다.

### 폴더 중복 삭제 사고 — 원인 규명 + 안전장치 + 구조 제거 (2026-08-18, 브랜치 `claude/folder-duplicate-deletion-bug-220309`)

**증상**: 폴더를 만들고 PC 를 껐다 켜니 같은 이름의 **빈 폴더**가 하나 더 보였고, 그것을 지우자 **원래 폴더가 통째로 사라졌다**(북마크는 미분류로 남음).

**원인 (재현 완료)**: 폴더는 **게임 단위 전역**(리그 필드 없음)인데 `renderList` 가 **리그 섹션마다 폴더 목록을 통째로 다시 그렸다**. 현재 리그 섹션은 빈 폴더도 보여주므로(2026-07-27 제보로 도입), 현재 리그 ≠ 북마크 리그가 되는 순간 폴더가 **0개짜리 복제본**으로 한 벌 더 나타난다. 그 복제본의 🗑 은 원본과 같은 `data-id` 라 `deleteFolder(원본 id)` 가 돈다. 북마크가 미분류로 간 것은 `deleteFolder` 의 정상 동작.

**왜 재부팅 후였나** — `ui.league` 가 실제 리그와 어긋나는 경로가 둘이다.
1. `leagueFromUrl()` 은 경로에 `search` 가 없으면 **`'Standard'` 를 하드코딩 반환**한다(`content-main.js`). 콘텐츠 스크립트는 `/trade/*` 전체에 붙으므로 거래소 첫 화면·**통화 교환 페이지**(`/trade/exchange/…`)에서도 패널이 뜨고 리그는 무조건 Standard 가 된다.
2. `mountPanel({ league: leagueFromUrl() })` 로 **마운트 시점에 고정**된다 — SPA 에서 리그를 바꿔도 갱신되지 않는다.

`resolveCurrentLeague` 는 페이지 리그가 살아있으면 무조건 1순위라, 살아있는 `Standard` 가 히스토리의 진짜 리그를 이긴다.

**① 삭제 안전장치 (`7faf159`)** — 확인만으론 이 사고를 **못 막는다**(사용자는 빈 폴더인 줄 알고 눌렀다). 실질 방어선은 되돌리기다.
- `deleteFolder` 가 되살릴 재료를 반환한다 — `{folder, index, movedIds}`. 폴더 **이름·색은 여기서만 남는다**
- `restoreFolder` 추가 — 원래 자리에 되살리고 북마크도 되돌린다. **삭제 후 사용자가 직접 다른 폴더에 넣은 북마크는 건드리지 않는다**(그 분류가 더 최신 의사)
- 🗑 은 **실제 보유 수**(화면에 보이는 수가 아니라) 기준 2클릭 확인. 빈 폴더는 마찰 없이 바로 지운다
- 지운 뒤 무엇이 지워졌는지 토스트로 알리고 **실행취소**를 준다(조건 묶음 삭제와 같은 언어)

**② 리그 섹션 제거 (`4e33b86`)** — 복제 자체를 없앤다. 미완료 10번을 여기서 해소했다.
- 북마크를 히스토리처럼 **리그 통합**으로 그린다. 폴더 그룹은 한 벌뿐
- 지금 보고 있는 리그가 **아닌** 북마크에만 행 리그 칩(`.ba-rowleague`) — 끝난 리그는 경고 톤, 살아있는 다른 리그는 중립 톤. 없어진 섹션 배지의 톤·문구를 계승. 대부분은 지금 리그라 평소엔 아무것도 안 뜬다
- `currentLeague` 를 못 정하면(null) 칩을 아예 안 붙인다 — 틀린 표식은 없느니만 못하다
- 간략 보기에선 리그명을 접고 트로피만 남긴다(`.ba-cond-n` 과 같은 처리) — 안 하면 칩 하나가 좁은 한 줄에서 제목을 먹는다(**실측 51→36px**, 수정 후 75px)
- 리그 섹션 접힘 상태(`collapsedLeagues`)·헤더 이벤트·투어의 섹션 펼치기·CSS 15줄 제거. **모션 순감**(chevron 회전 `.18s` 포함)

**검증**: 테스트 **508/508**(회귀 3종 신규 — 폴더 1벌·삭제버튼 1개·행 칩 톤) + 하네스 실브라우저에서 리그 섹션 0개·폴더 각 한 벌·`삭제→실행취소` 전 과정 클릭 확인.

**남은 판단거리** — `ui.league` 하드코딩 폴백(`'Standard'`)과 마운트 시점 고정은 **그대로 뒀다**. 리그 섹션이 없어져 영향이 "폴더 삭제 사고"에서 "리그 칩이 잘못 뜸"으로 내려갔기 때문. 칩 오탐 제보가 나오면 그때 `leagueFromUrl` 을 실시간화한다.

### 찜 상태 확인 — 일괄 → 개별, 요청 제한 대응 (2026-08-13, **미커밋 · 하네스 검증 완료**)

**질문에서 시작**: "가격확인을 브라우저 로딩 시마다 할 순 없을까? rate limit 에 걸릴까?"

| 규칙 | 한도 | 초과 시 정지 |
|---|---|---|

**변경 (사용자 결정: 찜마다 개별 확인)**

- `src/lib/tradeRate.js`(신규) — 실측 정책값에 묶인 순수 함수:
  `MIN_GAP_MS = 700`(계정 6/4초 = 667ms + 여유) · `nextDelay()` · `retryAfterMs()` · `parseRules()`

### 북마크 메모 기능 제거 (2026-08-13, **미커밋 · 하네스 검증 완료**)

**요청**: "북마크마다 있는 메모 기능은 삭제하자. 거의 사용하지 않는 기능 같아. 삭제하면 더 많은 북마크가 보일 것 같아."

**코드가 그 판단을 뒷받침했다** — `addBookmark`·`promoteToBookmark` 가 저장 시 `note` 를 `buildAutoNote()` 로 **자동으로 채우고 있었다.** 그래서 대부분의 메모는 사용자가 손대지 않은 자동 요약(`반지 · 타락 아니요 · 능력치 6개`)이었고, 조건 요약 칩과 내용이 겹쳤다.

**제거 범위 (사용자 결정: 데이터까지 삭제)**
- UI: `.ba-note-slot` 마크업 · 인라인 편집 · `.ba-note*` CSS 전부
- 저장: `setNote` 삭제, 자동 채움 2곳 삭제, **스키마 v1 → v2 마이그레이션으로 기존 `note` 필드 제거**
- `src/lib/autoNote.js` + 테스트: 유일한 소비자였던 store 가 안 쓰게 되어 고아 → 삭제

**검색 범위는 줄이지 않았다** — 예전 인덱스에 `note` 가 들어갔는데 그 내용이 `유형 + 비능력치 필터(label value)` 였다. 같은 재료를 원본에서 직접 넣도록 바꿔 `'반지'`·`'아이템 레벨'` 검색이 그대로 동작한다(테스트로 고정). 사라지는 건 **손으로 쓴 메모로 찾던 경우뿐**이고 그 데이터는 함께 지웠다.

**딸려 나온 정리 2건**
- **wide 밴드 폐지**: 카드 2층 병합은 '메모 줄'과 짝일 때만 조건 요약을 안 갉아먹었다. 짝이 사라지면 남은 후보(이름 줄 + 조건 요약)로 합쳐야 하는데 그건 599→600 잘림 급락(0→7건)의 재발이다. → `widthBand` 는 narrow/default 2단.
- **'간략히 / 상세히' 토글 제거**: 두 모드의 유일한 차이가 메모 줄 숨김이었다(CSS 주석에 "조건칩·⋯는 유지"라고 명시돼 있었다). 메모가 없으면 패딩 2px 차이뿐이라 눌러도 아무 일 없는 버튼이 된다. 액션 행 약 60px 회수 → **`actionRowBudget` 상한도 4항목/16자 → 3항목/11자로 함께 내렸다**(안 내리면 가드가 헐거워져 회수한 폭을 아무도 모르게 다시 채운다).

**결과 (하네스 실측, 최악 폰트)**

| 폭 | 카드 높이 | 액션 행 |
|---|---|---|
| 300 | 106px | 1줄(아이콘만) |
| 384 | **109 → 81px (-26%)** | 1줄 |
| 880 | 81px | 1줄 |

한 화면 북마크 수 **약 +33%**. 액션 행 문구는 `오래된 1 · 전체 접기 · 폴더 추가` 로 줄었다.

⚠ **되돌릴 수 없다** — v2 마이그레이션이 다음 로드 때 저장된 `note` 를 지운다. 손으로 쓴 메모가 있었다면 그 시점에 사라진다(사용자가 알고 결정).

### 조건 요약 말줄임 최소화 — '조건 경계'에서 끊기 (2026-08-13, **미커밋 · 하네스 검증 완료 · 라이브 미검증**)

**제보**: "말줄임표 되는 문제를 최소화하는 방법은 없을까?"

**먼저 잰 것 (사용자 북마크 26개)** — 잘림 비율:

|---|---|---|
| 300 | 69% | 69% |
| 384 | **15%** | 65% |
| 480 | 4% | 58% |
| 880 | **0%** | **46%** |

→ **이름은 384 이상에서 사실상 해결된다. 문제는 조건 요약이고, 880px 까지 넓혀도 절반이 잘린다.**

**후보안들을 계산해 전부 기각**
- **2줄 허용**: 65%→54%(384) / 46%→31%(880). 카드 +18px 를 내고 11~15%p 만 산다. wide 밴드의 '항목을 많이 보여준다'는 보상과 정면 충돌.
- **반복 단어 압축**: 요약 안에서 겹치는 단어를 다 지워도 **전체 절감 20%**. 최장 169자는 41% 줄여도 100자라 여전히 못 담는다.
- 근본 이유: 조건 요약 = 조건 수 × 스탯명 길이. 중앙값 44자인데 384px 의 가용은 약 16자다. **어떤 폭에서도 다 못 보여준다.**

**그래서 자르는 방식을 바꿨다** — 글자 중간이 아니라 `·` 경계에서 끊는다. 보이는 조건은 온전하고, 남은 개수는 이미 왼쪽 '조건 N개' 배지가, 전체는 호버 툴팁이 갖는다. CSS `text-overflow` 는 글자 단위라 불가능해 측정이 필요하다 → `src/lib/fitSummary.js`(순수 함수 `fitByParts` + DOM 적용 `fitCondSummaries`).

남은 6건은 ① 조건이 하나뿐이라 끊을 경계가 없거나 ② 첫 조건 자체가 가용폭보다 긴 경우 — 설계된 폴백이다.
⚠ **드래그 중 재측정은 라이브 미검증** — 검증 시점에 탭이 `hidden` 이라 rAF 가 멈춰 있었다. 렌더 시점 계산(renderList 에서 동기 호출)은 폭을 저장하고 새로고침하는 방식으로 384·880 양쪽 다 확인했다.

**300px 만 예외이고 그건 설계된 폴백이다** — 그 폭에서 `.ba-cond-tx` 가용은 **79px** 인데 조건 하나가 이미 ~101px 이라, "첫 조건조차 안 들어가면 원문을 그대로 두고 CSS 말줄임에 맡긴다"는 규칙이 발동한다(빈 칸보다 낫다). 오늘과 같은 모습이라 회귀는 아니다.
**후속 후보**: narrow 에서는 요약 텍스트를 아예 감추고 '조건 N개' 배지만 남기는 안 — 그 폭에서 요약은 어차피 정보가 아니라 잡음이다. 정보 손실이 있어 미적용.

**구현 함정 2개**
- **줄인 뒤의 `clientWidth` 는 '가용폭'이 아니라 '줄어든 내용의 폭'이다.** 그대로 다시 재면 넓혀도 복원되지 않고 줄어든 상태에 갇힌다 → 매번 ① 전부 원문 복원 → ② 읽기 → ③ 쓰기 순서로 돈다(읽기/쓰기를 섞으면 카드마다 강제 리플로).
- **백그라운드 탭에서는 `requestAnimationFrame` 이 멈춘다.** 폭 재측정을 rAF 로 묶어 뒀는데, 검증 중 대상 탭이 뒤에 있어 "넓혀도 안 늘어난다"로 보였다 — 코드 문제가 아니었다(탭을 앞으로 가져오니 정상). **하네스 검증 시 탭이 활성인지 먼저 확인할 것.** 실사용에서는 드래그 중 탭이 항상 활성이라 문제되지 않는다.
- 재측정 실패를 `catch (_) {}` 로 삼키고 있었다 → `console.warn` 으로 바꿨다. 삼키면 "넓혀도 조건이 안 늘어난다"로만 보여 원인 추적이 불가능하다.

### 패널 폭에 '넓게/좁게의 이유' 만들기 — 폭 밴드 (2026-08-13, **미커밋 · 하네스 검증 완료 · 라이브 미검증**)

**제보**: "넓게/좁게 사용할 때의 장단점들이 있어야 할 것 같아. 지금은 패널을 그저 넓히기만 하니까."

**wide 경계를 560 → 600 으로 올린 이유 (측정이 뒤집은 판단)**
줄을 합치면 조건 요약이 **이름 줄 폭만큼(~203px) 줄어든다.** 격차가 상수라 어느 폭에서도 wide 가 같은 폭 default 보다 넓어지지 않는다. 560 으로 두면 559→560 에서 조건 요약이 335 → 132px 로 **1px 넓혔는데 글자가 짧아진다** — 버그로 읽힌다. 그래서 **기본폭(384)보다 두 축 모두 나아지는** 지점으로 옮겼다: 600 에서 조건 요약 160→173px, 카드 109→75px. 손익분기 587 + 여유.
→ 결과적으로 폭마다 성격이 달라졌고, 그게 요청받은 "장단점"이다.

**⚠ wide 밴드가 합치는 짝을 바꿨다 (2026-08-13, 라이브 검증이 내 판단을 반박)**
처음엔 **이름 줄 + 조건 요약**을 합쳤다. 라이브 스윕(북마크 26개)에서 그게 회귀임이 드러났다:

| 520 | default | 25/26 |
| **560~599** | default | **26/26** |

**599 → 600 에서 잘림이 0건 → 7건.** 1px 넓혔더니 나빠지는, WIDE_MIN 을 600 으로 올릴 때 내가 피하려던 바로 그 증상이다. **기본폭 384 와만 비교해 경계를 정한 탓에**, 사용자가 실제로 지나가는 599→600 경로를 못 봤다.

→ **이름 줄 + 메모**를 합치고(`order` 0/1), **조건 요약은 단독 줄로 전체 폭**을 갖게 했다(order 2). 히스토리 카드(.ba-meta)는 메모 줄이 없고 칩도 짧아 기존대로 이름 줄과 합친다.
**수정 후 — 라이브 확인 완료(북마크 26개)**: 384 20/26 · 480 23/26 · **560·599·600·640·720·880 전부 26/26 온전** — 599→600 급락 소멸(19→26). 카드 높이 109 → 82px(-25%)로 층수 이득 유지. 300(narrow) 11/26 은 설계된 폴백.

**wide 는 grid 가 아니라 flex-wrap** — 이름이 아주 길면 메타 행이 스스로 내려가 **지금과 똑같은 레이아웃으로 되돌아간다.** grid 로 칸을 못 박으면 그 경우 이름이 찌그러진다. 폭 예산이 세 번 깨진 영역이라 '넘치면 원래대로'가 되는 쪽을 택했다.
`flex-basis` 는 0 이어야 한다 — 처음에 220px 로 뒀더니 그 값이 줄바꿈 판정에 들어가 **560px 에서도 안 붙었다**(이름 줄 자연폭 중앙값 192·최대 289px). basis 0 + `min-width: 150px`.

**측정 함정 2개 (다음에 또 걸린다)**
- `.ba-row { content-visibility: auto; contain-intrinsic-size: 96px }` — 화면 밖 카드는 **자리표시자 크기(96px)를 보고한다.** 처음 측정에서 카드 높이가 전 폭 116px 로 나와 "wide 가 안 먹는다"고 오판했다. 측정 중에는 `content-visibility: visible` 을 강제해야 한다.
- 액션 행 줄 수를 자식 `top` 의 고유값으로 세면 **아이콘 묶음의 세로 정렬 차이가 줄바꿈으로 잡힌다.** 6px 허용오차로 묶어야 한다.

**부수 수정** — `applyWidth` 가 저장값이 있을 때만 불려서 **첫 사용자는 `data-w` 없이 떴다**(밴드 CSS 전체가 죽는다). 저장값 읽기 전에 한 번 부르도록 고쳤다. `clampPanelWidth` 는 `Number(null)===0` 때문에 "값 없음"이 "0px 요청"으로 읽혀 최소폭까지 쪼그라들던 것도 테스트가 잡아 고쳤다.

### 조건 묶음 — 능력치 필터만 담기 + 로드 중 토스트 (2026-08-13, **미커밋 · 라이브 미검증**)

**제보 A: "조건 묶음으로 저장할 때에는 능력치 필터에 관련된 정보만 저장되어야 해. 현재는 아이템 검색 정보도 저장된다."**

`extractConditionSet` 이 `q.type` 을 함께 담고, `mergeConditionSet` 이 `q.type = set.itemType` 으로 **대상 검색의 아이템을 덮어쓰고** 있었다. 그러면 '얹기'가 아니라 '바꾸기'다. `q.type` 은 '아이템 검색' 칸에서 고른 기본 타입이다(아이템 유형 드롭다운은 `filters.type_filters.category` 로 별개이며 애초에 담지 않는다).
- `extractConditionSet` — `itemType` 제거. 능력치가 하나도 없으면 `null`(유형만으론 묶음이 되지 않는다).
- `mergeConditionSet` — `q.type` 을 건드리지 않는다. **예전에 저장된 묶음의 `itemType` 은 여기서 무시되므로 저장분 마이그레이션이 필요 없다**(테스트로 고정).
- `conditionSetSummary` — 유형 제거. 남아 있는 `itemType` 을 보여주면 "이것도 적용된다"는 잘못된 인상을 준다.
- `panel.js addStatsToSearch` 의 `{ ...set, itemType: null }` 은 이 변경으로 고아가 돼 제거(같은 일을 공통 경로가 한다).

**제보 B: "툴팁이 페이지 새로고침되는 과정에서 이상하게 계속 보이는 문제"**

정체는 툴팁이 아니라 **패널 토스트**(`.ba-toast`, 뷰포트 42% 지점 고정)였다. 조건을 얹고 이동한 뒤 뜨는 안내다. 원인 2개:
- 우리 패널은 `document_idle` 에 뜨는데 거래소 화면은 한참 뒤에 그려진다 → **아무것도 없는 빈 화면 한가운데** 토스트만 떠 있다(제보 스크린샷이 정확히 그 상태). 게다가 그동안 메인 스레드가 막혀 자동 숨김 타이머(2.2s)도 늦게 돌아 더 오래 남는다. → **`load` 이후에 띄운다**(3초 상한 — 클릭과 안내가 너무 벌어지면 무슨 안내인지 모른다).
- `chrome.storage.local.remove('baSetApplied')` 를 **await 하지 않아서**, 거래소가 로드 중 한 번 더 이동하면 안 지워진 플래그가 다음 로드에서 또 토스트를 띄울 수 있었다. → 띄우기 **전에** await 로 소비. 15초 지난 흔적도 이제 함께 정리된다(예전엔 조기 return 이라 영구 잔류).

⚠ **반복 재현은 못 했다** — 단순 새로고침으로는 토스트가 뜨지 않았다(플래그는 소비되고 있다). 다만 폴링이 로드 8.6초 뒤에야 시작돼 초기 구간은 관측하지 못했다. 위 두 원인은 제보 스크린샷(빈 화면 + 토스트)과 코드 상 경합으로 확정한 것이며, 리로드 후 실사용 확인이 필요하다.

### 조건 묶음 칩을 거래소 화면에도 (2026-08-13, **미커밋 · 라이브 미검증**)

**요청**: "우선 패널에 두고 사용해보니, 눈에 띄지 않아서 사용성이 조금 아쉬웠어. DOM이 바뀌면 그때마다 우선 대응하는 걸로 하고, DOM에도 추가해보자."

**문제는 기능이 아니라 위치였다** — 조건을 만지는 동안 시선은 거래소 필터에 머무는데 칩은 화면 반대편 패널에 있었다. 그래서 **패널 칩은 그대로 두고**, 조건을 실제로 넣는 자리 바로 위(능력치 필터 그룹 맨 앞)에 같은 줄을 하나 더 놓는다.

**앵커는 실측으로 정했다** (라이브 DOM에서 능력치 필터 입력칸의 조상 사슬을 직접 읽음):
```
.filter-group (제목 "능력치 필터")
  ├ .filter-title.filter-title-clickable
  └ .filter-group-body        ← 여기 firstChild 로 삽입
      └ .filter.filter-padded  ← 첫 번째 능력치 필터
```
탐색 2경로: ① `.filter-group-body input[placeholder]` 중 `+ 능력치 필터 추가` → `closest('.filter-group-body')` ② 폴백 — 그룹 제목 텍스트. **라이브 검증: 12개 `.filter-group` 중 두 경로 모두 능력치 그룹만 골랐고 서로 일치.** 한/영 정규식(`능력치 필터` / `stat filters?`).

**유지보수 계약 (사용자 수용)** — 거래소가 마크업을 바꾸면 앵커를 못 찾는다. 그때는 던지지도, 아무 데나 붙이지도 않고 **조용히 아무것도 하지 않는다**. 패널 칩이 그대로라 기능은 사라지지 않고 화면만 예전으로 돌아간다. **앵커가 깨지면 `src/lib/pageSets.js` 하나만 고치면 된다** — 거래소 마크업 의존을 이 파일에 가뒀다.

**무한 루프 함정** — 주입 감시가 `document.body` 전역 MutationObserver 라, 매번 새로 그리면 우리 삽입이 감시를 다시 깨운다. `dataset.sig`(묶음 id+이름 JSON) 비교로 **같은 내용이면 노드를 재사용**한다. 회귀 테스트로 고정(`pageSets.dom.test.js`).

**배선**
- 렌더 트리거: `pobKick`(옵저버·100ms 디바운스) / `schedulePobInject` 타이머 / `storage.onChanged`(`conditionSets`) / 진입 직후 `[200,800,2000]ms`.
- **옵저버를 첫 fetch 가 아니라 진입 직후에 켠다** — 조건 줄은 검색 결과가 없어도(필터만 펼친 상태) 필요하다.
- 실패 문구는 패널과 **같은 사본**을 쓴다: `SET_FAIL` 을 `panel.js` 로컬 → `lib/conditionSet.js` 로 옮겨 양쪽이 import.

**과거 사고 두 건이 정확히 이 작업의 위험군이었다**

**툴팁 본문은 패널과 같은 함수에서 나온다** — `conditionSetTip(set)` 을 `lib/conditionSet.js` 에 두고 패널·페이지가 함께 쓴다(패널에 인라인으로 있던 사본 제거). 두 표면이 갈라지지 않게 테스트로 고정.

**남은 것**: 확장 리로드 후 라이브 확인 — 칩이 실제로 뜨는지 / 클릭 시 조건이 얹혀 이동하는지 / 이동 후 패널 토스트가 뜨는지 / 묶음 0개면 줄이 안 뜨는지 / 호버 툴팁 위치.

### "Extension context invalidated" 콘솔 오류 + 죽은 패널 무안내 (2026-08-06, **미커밋**)

**제보**: 확장 리로드 후 `Uncaught (in promise) Error: Extension context invalidated.` × 4 (`content-main.js`).

**성격**: 확장을 리로드·업데이트하면 **이미 열려 있던 탭**의 콘텐츠 스크립트는 고아가 되고 이후 모든 `chrome.*` 호출이 던진다 — **브라우저 동작상 정상**이다. 문제는 우리가 그걸 **안 잡아서** ① 콘솔이 uncaught 로 더럽혀지고 ② **사용자는 패널이 왜 죽었는지 모른 채 남는다**는 것.

**샌 곳 2군데(자동 실행 경로라 클릭 없이도 터진다)**
- `ensureSchema()` — 최상위에서 캐치 없이 호출. 리로드 직후 바로 던진다
- `window.addEventListener('message', async …)` — **async 리스너**라 내부에서 던지면 그대로 unhandled rejection. 안에서 `addHistory`·`markUsedByUrl`·`backfillQuery`가 `chrome.storage`를 만진다. **검색할 때마다 발생**해서 오류가 여러 개였던 것도 이걸로 설명된다

**수정**
- `isCtxInvalidated()` + `noteExtensionDead()` — 무효화를 식별해 **1회만** 안내. 배너에 **[새로고침] 버튼**을 달아 복구 경로를 준다(값은 전부 `textContent`)
- `guard(p)` — 자동 실행 진입점 2곳(`ensureSchema`, bridge 핸들러)에 적용. 리스너 본문은 `handleBridgeMessage()`로 분리해 감쌌다

**설계 판단 3건**
1. **`origin`을 키의 일부로 쓴다**(`listingId+origin`) — 카카오와 글로벌은 **매물 id 공간이 다르다.** 합치면 한쪽에서 조회했을 때 멀쩡한 매물이 `null`로 와서 **"판매됨"으로 조용히 오판**한다. 이번 세션에서 반복해 나온 부류라 미리 막았다
2. **`sourceUrl`로 재검색한다** — 아이템→조건 역추출(item → query)을 만들지 않는다. `conditionSet.js`는 raw query 기반이라 item 입력을 지원하지 않아 역추출은 그 자체로 대형 작업이다. 찾았던 검색을 다시 열면 충분하다
3. **상태 갱신은 사용자가 누를 때만** — 자동 폴링 없음(rate limit). 장기 보관 용도라 목록을 여는 순간이 곧 확인 시점이라 자동화 이득이 작다. **실제로 쓰이는 게 확인되면 그때 얹는다**

**구현**
- `store.js` — `watchlist` **별도 키**(records와 생명주기가 달라 `conditionSets`·`folders`와 같은 근거). `listWatched`/`addWatch`/`removeWatch`/`isWatched`/`applyWatchStatus`, `WATCH_CAP = 100`
  - `addWatch`는 **조용히 버리지 않는다** — 중복·상한 초과 시 `{ok:false, reason}`을 돌려주고 UI가 토스트로 알린다
  - `applyWatchStatus`는 **넘긴 항목만** 갱신 — 확인 못 한 것(다른 거래소)을 `sold`로 떨어뜨리면 거짓말이 된다
- `content-main.js` — 결과 행 ★ 버튼. PoB 버튼과 **한 그룹**(`.ba-row-btns`)으로 묶어 기존 3단 배치 폴백을 그대로 상속(신규 순회 0). `listing.account.name` 캡처 추가
- `renderList.js` — '찜한 매물' 섹션(북마크와 히스토리 사이). 배치 10개 **순차** 재조회, **현재 페이지와 origin이 같은 매물만** 대상이고 나머지는 `다른 거래소` 배지로 명시
- `panel.js` — `toast`를 반환 API에 노출(페이지 표면 ★에서도 같은 토스트를 쓰기 위해)
- `panel.css` — 상태 배지. ⚠ **`--ba-drop`(라임)은 '드래그로 놓을 자리 전용' 토큰이라 재사용하지 않았다.** '있음'은 일부러 약하게 두고 **'판매됨'만 강조** — 강조를 나눠 가지면 둘 다 안 보인다

**미착수**: 자동·주기 갱신, 판매자 찜(거래소 `account` 필터로 대체), 아이템→조건 역추출, 타 origin 원격 확인(서비스 워커 경유)

**일몰 조건**: 한 리그(≈3개월) 내 찜 생존율 20% 미만 또는 사용자 5% 미만이면 축소·제거 검토

검증: 테스트 **354/354**(신규 10건 — origin 분리·상한 거부·미확인 항목 불변 포함), 빌드 통과. 하네스 실측: 배지 4종 렌더·가격 변동(`3 divine → 5 divine`)·긴 이름 말줄임·오버플로 없음·해제 동작·**실패 경로(토스트+버튼 복구+카드가 sold로 오변경되지 않음)**·콘솔 에러 0. **실제 거래소에서의 ★ 주입·상태 확인은 사용자 확인 필요**(하네스엔 결과 행·실 API가 없다)

### 한↔영 거래소 전환 — geo-redirect 전제 오진 정정 + 챌린지 대응 (2026-08-06, **미커밋**)

**결론부터: 프로젝트가 오래 믿어온 "pathofexile.com이 한국 IP를 카카오로 geo-redirect한다"는 전제가 측정으로 뒷받침되지 않는다.** 실제로 걸리는 건 Cloudflare 봇 챌린지이고, 화면이 깜박이던 원인의 상당 부분은 **우리 확장이었다.**

**측정 (KR IP, curl)**
| 대상 | 결과 |
|---|---|
| `/trade` | `403` `Cf-Mitigated: challenge`, **Location 없음**, `CF-RAY: …-ICN` |
| `/trade2` | **`/trade`와 동일** |
| `/api/trade/data/leagues` | `200` |

- **리다이렉트가 아니다** — 3xx도 `Location`도 없다. 봇 차단이다
- **`/trade`와 `/trade2`가 동일** → `cross-site-receiver.js` 주석·`CLAUDE.md`·배포 문서의 "PoE1만 접근 가능, PoE2만 geo-redirect"는 **근거 없는 서술이었다**
- **API는 통과** → 예전에 "API는 되는데 사이트는 안 된다"를 geo 근거로 읽었지만, 실제로는 **챌린지가 HTML 경로에만 걸리는 것**이다
- **사용자 확인**: 확장을 끄면 깜박임이 사라지고 pathofexile에 그대로 머문다. 단 **재현율이 매우 낮아** "geo-redirect가 없다"고 확정하진 못한다

**원인 A — 우리가 봇 점수를 올리고 있었다**
`page-bridge.js`가 MAIN world·`document_start`에서 `window.fetch`·`XMLHttpRequest.prototype`을 교체한다. 관찰 전용이라 동작엔 영향이 없지만 `String(window.fetch)`가 `[native code]`가 아니게 되어 봇 탐지에 걸린다.
- `mask()` 신설 — `name`·`length`·`toString`을 원본으로 위임하고 **`toString` 자신도 네이티브로 보이게** 한 겹 더 덮는다
- 하네스 실측: 후킹 전후 문자열 **완전 동일**(`function fetch() { [native code] }`), fetch·XHR 캡처는 정상 유지, 무관한 요청은 미캡처

**원인 B — 실패하면 복구가 불가능했다**
`cross-site-receiver.js`가 **fetch 직전에** 페이로드를 지웠다. 챌린지에 걸리면 검색 조건이 이미 사라진 뒤라 확인 절차를 마치고 새로고침해도 영영 복구가 안 됐다.
- **성공했을 때만 소비**하도록 바꾸고, 챌린지 루프로 새로고침이 반복될 때 POST가 무한히 나가지 않게 **시도 3회 상한**(`tries`)을 뒀다
- 실패 시 **화면에 보이는 안내 배너**(`notify`) — 종전엔 `console.warn`뿐이라 사용자는 영문을 몰랐고, 드물게 터지는 이 실패가 아무 흔적도 안 남겨 **원인 판정이 영영 불가능했다.** 문구에 HTTP 상태·현재 호스트·시도 횟수를 담아 **다음 발생이 곧 제보 자료**가 되게 했다
- ⚠ **`notify`를 export 하지 않는다** — 모듈이 되면 crxjs가 동적 import 로더로 바꾸는데, 챌린지 페이지의 엄격한 CSP(`script-src 'nonce-…'`)에 그 import가 막힐 수 있다. **정작 안내가 필요한 화면에서 스크립트가 안 뜨면 의미가 없다.** 빌드 산출물에서 loader가 아닌 직접 주입임을 확인했다

**manifest**: `cross-site-receiver`에 `https://www.pathofexile.com/trade2/*` 추가 — 종전엔 `/trade/*`만 매치돼 **poe2 전환은 지역과 무관하게 구조적으로 불가능**했다

**정정한 문서**: `CLAUDE.md`(프로젝트) · `docs/chrome-webstore-배포.md` · `docs/영문-pob-복사-선행조사.md`. 참조하던 메모리 `project_poe_bookmark_atlas_georedirect`는 **실재하지 않는다**

**전환 기능은 여전히 UI에서 숨김 유지** — 근거가 "한 번 안 일어났다"뿐이라 약하다. 위 안내 배너로 사례를 몇 건 모은 뒤 복원 여부를 판단한다.

검증: 테스트 **344/344**, 빌드 통과, 하네스 실측(위장·캡처·배너 렌더 560px 상한/중앙정렬/화면 안), 빌드 산출물에 핵심 문자열 포함 확인.

### PoB 조립기 — 조용한 실패 가시화 + 미독해 필드 3종 (2026-08-05, **미커밋**)

군단 주얼 수정 뒤 "같은 부류가 더 있나" 조사에서 나온 3건을 처리했다.

**① 값 초과 경고 — 실패 처리하지 않는다(측정 근거)**
- `fillValues`는 값이 템플릿 `#`보다 많으면 초과분을 조용히 버린다 → 틀린 수치가 PoB로 간다
- ⚠ **그런데 실측하니 진짜 유실은 사실상 0건이었다.** 번들 맵의 ko/en 쌍(poe1 465·poe2 160)에서 초과 122건 중 **120건이 `#`=0인 고정 문구**("추가 **1**명" → "an additional Rogue Exile" — 한국어 어법상의 1이라 EN이 온전). 나머지 2건도 "5개 또는 6개"가 EN에 리터럴로 들어간 정상 케이스
- 따라서 **`#`가 1개 이상일 때만** 보고, **실패가 아니라 경고**로 남긴다. 실패로 만들었으면 정상 번역 120건이 한글로 떨어졌다. **이건 고장을 고친 게 아니라 앞으로를 위한 계기판이다**
- ⚠ 이 측정은 `ko`를 가진 다중변형 항목만 덮는다(전체 17,684 중 465). 단일 템플릿 항목의 실제 위험은 측정 불가 — 경고가 그걸 드러내라고 있는 것

**② 변형 추정 경고** — `pickTemplate`이 다중변형에서 ko 매칭 실패 시 조용히 `e[0]`을 썼다(다중변형 poe1 233·poe2 80건, 1.0~1.3%). `(Local)`/글로벌을 잘못 고르면 PoB 계산이 통째로 달라진다. `pickTemplateInfo(id, ko, map)` 신설 → `{en, guessed}`. **동작은 유지하고 경고만 추가**(기존 `pickTemplate`은 얇은 래퍼로 남겨 호출부·테스트 불변)

**`warnings[]`를 `missing[]`과 분리한 이유**: warnings까지 "미변환 N" 배지에 세면 정상 복사가 실패처럼 보인다. `buildPobText`가 `{text, missing, warnings}` 반환, 배지는 `missing`만, 제보 텍스트(`buildReportText` 4번째 인자)엔 '의심 항목' 절로 따로 담는다. **warnings만 있어도 제보는 생성된다**(그게 드러내려는 대상이므로)

**③ PoB가 읽는데 안 만들던 필드 3종** — Radius는 "`properties`를 안 읽는다"의 한 사례였을 뿐이었다
- **품질** `Quality: +20%` — PoB 로컬 mod 계산에 직접 영향
- **소켓·링크** `Sockets: R-G-B W` — 같은 `group`은 `-`, 다른 group은 공백
- **영향력** `Shaper Item`/`Elder Item`/… 6종
- 섹션 순서를 인게임 Ctrl+C에 맞췄다: 헤더 → 속성(품질·반경) → 소켓 → Item Level → mod → 영향력 → Corrupted
- 미착수(저우선): `requirements`·`identified`·`synthesised`·`duplicated`·`scourgeMods`·`veiledMods`·`crucibleMods`

**결백 확인**: `hashAt`의 위치 기반 매칭을 의심했으나 캡처 실데이터 대조 결과 `hashes[i] ↔ mods[i]` 대응이 맞다(`[hash, [n]]`의 `[n]`은 mod 인덱스가 아니다). 버그 아님

검증: 테스트 **344/344**(신규 8건), 빌드 통과. **PoB 실제 붙여넣기 사용자 확인 완료(2026-08-05)** — 군단 주얼·품질·소켓·영향력 정상 동작

### PoB 영문 복사 — 군단 주얼(무궁한 주얼) 정복자 줄 유실 + 반경 미출력 (2026-08-05, **미커밋**)

**제보 증상**: 고상한 오만(Elegant Hubris)을 PoB에 붙여넣으면 `Radius: Large`와 `Passives in radius are Conquered by the Eternal Empire`가 없다. 사용자가 **PoB가 인식한 데이터**를 정상본과 나란히 제시.

**원인 A — 두 줄짜리 mod의 뒷줄이 조용히 사라진다 (일반적 결함)**
- 거래소는 군단 주얼 mod를 **두 줄 한 덩어리**로 준다: `카스피로를 기념하기 위해 제작한 주화 20820개\n반경 내 패시브 스킬은 영원한 제국의 지배를 받음`

- `translateMod`이 `#`가 다 채워졌다는 이유로 성공 처리하고 즉시 반환 → **둘째 줄은 존재 자체가 사라졌다.** `missing[]`에도 안 남아 **Shift+클릭 제보로도 영영 안 드러나는** 조용한 유실이었다
- **폴백 사전으로는 못 고친다**: `pobUniqueModMap.poe1.json`의 군단 주얼 5종은 주얼당 정복자 1명뿐(고상한 오만은 Cadiro) — poe-i18n 소스가 "유니크 1개 = mod 1쌍"이라 Caspiro·Chitus·Victario 변형이 없다. 게다가 stat id 경로가 **성공해버려서 폴백을 보지도 않았다**
- 수정: `withTrailingLines()` 신설 — 템플릿이 덮은 줄 수보다 KR 줄이 많으면 **남은 줄을 각각 폴백 사전으로 재번역**한다. 실패한 줄은 **KR을 남기고**(줄을 버리지 않는다) `missingLines`로 반환 → `modLines`가 줄 단위로 `missing[]`에 보고. `translateMod` 반환에 `missingLines` 추가(선택 필드 — 단일 줄 mod는 종전과 완전히 동일)
- ⚠ **가정**: 템플릿이 mod의 **앞줄부터** 덮는다. 검색 stat이 mod 선두 문구에서 만들어지므로 성립하지만, 어긋나는 사례가 나오면 여기부터 의심할 것

**원인 B — `properties`를 아예 안 읽었다**
- `buildPobText`에 `properties`·`Radius`가 **한 번도 등장하지 않았다**(`src/`·`test/` 전수 확인). 주얼 반경은 PoB가 '반경 내' 효과 계산에 실제로 쓴다
- `radiusLine()` 신설 — `properties`에서 반경을 뽑아 `대형/중형/소형 → Large/Medium/Small` 변환. 인게임 Ctrl+C 순서대로 **헤더 → 반경 → Item Level → mod** 섹션에 배치. 모르는 표기는 그대로 내보내되 `missing`에 `radius:<원문>`으로 남긴다

**정복자 문구 5줄을 overrides에 추가** (`scripts/pob-mod-overrides.poe1.json`, 종전 `{}`)
- 정복자는 20명(5주얼×4)이지만 **진영은 5개**라 5줄이면 끝난다. 값은 기존 사전 항목에서 **프로그램으로 추출**해 추측이 없다(바알·카루이·마라케스·템플러·영원한 제국)
- ⚠ **`src/lib/pobUniqueModMap.poe1.json`에도 같은 5키를 직접 병합했다(464 → 469키).** 빌드 스크립트 재실행은 poe-i18n 소스 + stats 원본이 필요하고 **464키가 통째로 흔들릴 위험**이 있어 피했다. overrides 파일에 기록해 뒀으므로 다음 정식 재생성 때 그대로 보존된다(overrides는 항상 승). 충돌 0건 확인

- **`initFuzzyPrefix()`를 async로 만들지 않았다** — 설정을 `await`하면 페이지 로드 직후 1.2초 자동포커스 가드 창을 저장소 응답 대기에 갉아먹혀 회귀가 난다. 리스너는 즉시 붙이고 **동작만 모듈 레벨 `enabled` 플래그로 가른다** + `storage.onChanged` 구독으로 새로고침 없이 반영
- **끄더라도 '페이지 로드 시 자동 포커스 해제'는 유지한다** — 제보와 무관한 별개 편의 기능이라 한 토글에 묶으면 `~`만 끄려던 사용자가 그것까지 잃는다
- ⚠ **두 세그먼트가 `.ba-set-opt`를 공유**한다 → 기존 핸들러의 `querySelectorAll('.ba-set-opt')`를 `[data-side]`/`[data-fz]`로 갈랐다. 안 갈랐으면 퍼지 클릭이 `applySide(undefined)`를 불렀다(하네스에서 패널 위치가 안 흔들리는 것으로 확인)

**곁들여 고친 것**: `.ba-seg > *`에 누름 피드백이 없었다 — 패널의 다른 누름 요소(`.ba-set-go`·`.ba-set-del`·`.ba-toast-act`)는 전부 `:active { scale }`+reduced-motion 가드를 갖는데 세그먼트 3곳(정렬 토글·패널 위치·신규 퍼지)만 빠져 있었다. 같은 값(.16s·`--ba-ease-out`·0.97)으로 맞췄다. `review-animations` **Approve**.

**테스트 목 보강**: `test/setup.js`에 `chrome.storage.onChanged` 추가 + `__fireStorageChange(changes, area)` 수동 발화기. **`set()`이 자동 발화하지는 않는다** — 그러면 다른 테스트의 리스너가 예기치 않게 깨어난다.
