# 패널 화면 정리 — 섹션 순서·접기 + 상단 간결 + 로딩 안내

## 배경

커뮤니티 제보(2026-09-04, `v0.12.0` 의 일괄 삭제·교체 가져오기를 요청했던 것과 **같은 제보자**):

1. 파일 불러오기·목록 갱신에 딜레이가 있는데 안내가 없어 "중간에 꼬인다"
2. `타이틀 → 북마크 → 찜한 매물` 순서가 고정이라 순서를 바꾸고 싶다. 북마크 전체 접기도.
3. 상단 타이틀·저장·시세를 하단으로 내리거나 숨기고 싶다
4. 찜한 매물 시세 일괄 조회 / 갱신 간격 설정 — **이번 범위 밖**(후속)

시즌 끝물이라 북마크보다 **찜한 매물을 더 자주 본다**는 것이 이 요청 전체의 동기다.
"눈이 높아져 찜 리스트가 한 창에 안 보인다"가 실제로 겪는 증상이다.

## 범위

①②③ 만 한다. ④는 별건으로 남긴다 — 아래 「후속」 참조.

## 데이터

`chrome.storage.local`, 기존 `ui*` 관용구, 게임 공통.

| 키 | 기본값 | 뜻 |
|---|---|---|
| `uiSecOrder` | `['bookmarks','watch','history']` | 섹션 순서 |
| `uiCollapsedSecs` | `[]` | 접힌 섹션 키 |
| `uiHeadCompact` | `false` | 상단 간결 모드 |

`uiSecOrder` 는 읽을 때 **정규화**한다 — 모르는 키는 버리고 빠진 키는 뒤에 채운다.
섹션이 늘거나 줄어도 옛 설정이 화면을 지우지 않게 하는 유일한 방어다.

## ② 섹션 순서 + 접기

**`src/lib/secOrder.js`(신규, 순수)** — `SECTIONS` · `normalizeSecOrder` · `moveSection` · `SECTION_LABEL`.
저장 형식을 아는 곳을 한 군데로 모은다(renderList 와 설정 모달이 둘 다 쓴다).

**`renderList.js`** — `html +=` 로 이어붙이던 것을 조각 3개로 나눠 순서대로 join 한다.

- `bookmarks` = `.ba-list-head`(제목+검색) + `.ba-sec-body`(액션 행 + 폴더 그룹 + 빈 상태)
- `watch` = 찜 헤더 + `.ba-sec-body`(찜 행)
- `history` = 히스토리 헤더 + `.ba-sec-body`(행 + 더 보기)

각 조각을 `<div class="ba-sec" data-sec="…">` 로 감싼다. `.ba-list` 에는 자식 선택자 CSS 가 없어
감싸도 안전하다(확인함). `.ba-list-head` ↔ `.ba-sec-head` ↔ `.ba-search-row` 의 부모·형제 관계는
그대로 유지된다 — `test/panelBands.dom.test.js` 가 그 계약을 이미 지키고 있다.

**접기**: 세 섹션 헤더의 `.ba-sec-title` 을 클릭 대상으로 만들고 chevron 을 붙인다.
폴더 헤더와 **같은 언어**(chevron 회전 + 본문 `display:none`)라 새로 배울 게 없고, 버튼을
더하지 않으므로 액션 행 폭 예산에 영향이 0 이다.

- 접혀도 **헤더와 개수는 남는다** — 몇 개 있는지가 계속 보여야 한다.
- **북마크를 접어도 검색행은 남는다.** 그 검색창은 북마크와 히스토리를 **동시에** 훑으므로,
  북마크를 접었다고 사라지면 히스토리를 찾을 방법이 없어진다.
- 섹션 간 간격은 `.ba-sec + .ba-sec { margin-top: 22px }` 로 옮긴다. 지금은 히스토리 헤더에만
  붙어 있어 순서가 바뀌면 간격이 따라오지 않는다.

**폭 예산**: chevron 은 `.ba-sec-title` 을 약 19px 넓힌다. m 밴드(500px↑)에서 제목·검색·정렬이
한 줄로 합쳐지는데, 그 줄에서 `.ba-search-row` 가 `flex:1; min-width:0` 이라 **검색창이 그만큼
줄어들 뿐 줄바꿈은 나지 않는다.** 하네스에서 실측해 확인한다.

**순서 변경 UI**: 설정 모달에 `data-setting="secorder"` 항목을 더한다. 세 줄을 ▲▼ 로 옮긴다.
패널 본문의 폭 예산을 전혀 건드리지 않고, 이미 있는 '설정 둘러보기' 투어가 사용자를 그리로 데려간다.

## ③ 상단 간결 모드

`.ba-root[data-headcompact="1"]` 속성 하나로 처리한다.

- `.ba-head` 숨김 — 브랜드 로고·타이틀·제작 칩·후원 링크
- `.ba-econ-row` 의 `.ba-econ-btn`(아이템 시세·시장 동향) 숨김
- **`현재 검색 저장` 은 남긴다** — 핵심 동작이라 숨기면 Alt+S 를 모르는 사용자가 기능을 잃는다
- **⌨ 단축키 칩은 잃지 않는다.** 단축키 목록은 그 팝오버에만 있다. 간결 모드에서 요소를
  `.ba-econ-row` 로 **옮긴다**(마크업은 한 벌, 복제 없음). 시세·동향이 빠져 자리가 남는다.
  팝오버는 `mouseenter` 에서 칩의 rect 로 위치를 계산하므로 옮겨도 그대로 동작한다.

`briefOn` 과 같이 **localStorage 거울(`baPanelLayout`)에도 쓴다** — 첫 프레임부터 이 값으로
그리지 않으면 상단이 잠깐 보였다 사라지는 게 눈에 띈다.

설정 모달에 `data-setting="header"` 세그먼트(`표시`/`간결`) + 둘러보기 스텝 1개.

## ① 로딩 안내

두 구간이 성격이 다르다.

**가져오기** — 파일 선택 → 읽기 → 파싱 → (교체면 백업 다운로드) → 저장 → 재렌더.
이 전 구간에 표시가 하나도 없고 **다시 눌러도 막히지 않는다.** 중복 실행 차단이 실제 값어치다.
버튼을 진행 상태로 잠그고, 적용 구간에 "가져오는 중…" 을 띄웠다 완료 토스트로 바꾼다.

**목록 갱신** — **재봤고, 만들지 않기로 했다.**

| 데이터 | jsdom (vitest) | **실제 크로미움 (하네스)** |
|---|---|---|
| 북마크 200 + 히스토리 300 | 440~670ms | **37~45ms** (4런) |
| 북마크 400 | — | 63~93ms (3런) |
| 북마크 800 | — | 121~173ms (3런) |

**jsdom 값을 근거로 삼았으면 있지도 않은 문제에 스피너를 달 뻔했다** — innerHTML 파싱이
느려 실제의 12배로 나온다. 실제 브라우저에서는 800개에서도 사람이 못 느끼는 구간이라,
여기에 표시를 붙이면 도움이 아니라 깜빡임만 는다.

그러면 제보자가 느낀 딜레이는 어디인가 — **가져오기 파이프라인**이다(파일 대화상자 → 읽기 →
파싱 → 백업 내려받기 → `chrome.storage.local` 쓰기). 하네스의 목 storage 는 인메모리 Map 이라
**저장 지연이 재현되지 않는다.** 실제 확장의 storage 쓰기 지연은 여기서 잴 수 없다. 위 잠금·
진행 표시가 정확히 그 구간을 덮는다.

## 후속 — ④ 찜 시세 일괄 조회

**④-b 갱신 간격 설정(자동 주기)은 받지 않는다.** 프로젝트 「기능 수용 기준」의 *백그라운드 상시
동작*에 걸린다 — 조용히 죽는 실패가 되고, 429 가 나면 그 정지가 `/api/trade/fetch` 엔드포인트
단위라 **사용자의 실제 거래소 검색까지 멈춘다.** 라이브 매물 알림을 거절한 것과 같은 이유다.

**④-a 일괄 조회는 받을 수 있다** — 단 순차 + 700ms 간격 + 진행률 + 중단이 전제다.
2026-08-13 에 뺀 그 버튼은 대기 없이 10요청을 쐈던 것이라 성격이 다르다. 찜 100개면 70초가
걸리고 IP 5분 한도(100)에 딱 붙으므로, 한 번에 다 도는 대신 상한·중단을 어떻게 둘지가 설계의 전부다.
