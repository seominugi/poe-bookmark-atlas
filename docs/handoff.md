## 완료된 작업

### PoB 영문 복사 — 옵션형 stat id(`id|N`) 미매핑 수정 (2026-08-02, 미커밋)
- **제보 증상**: 소형 클러스터 주얼을 PoB 복사하면 `Adds 2 Passive Skills (enchant)`는 영문인데 바로 다음 줄이 `추가된 소형 패시브 스킬 효과: 방어도 15% 증가 (enchant)`로 한글로 남았다
- **원인**: 거래소 stats API는 **선택지가 있는 mod를 옵션 번호까지 붙인 별개 id**로 준다 — `enchant.stat_3948993189|42` = "Added Small Passive Skills grant: 15% increased Armour". 아이템 `extended.hashes`도 같은 형태다. 그런데 번들 맵에는 옵션 번호 없는 통합 id(`enchant.stat_3948993189` → `"...grant: #"`)만 있어 조회가 실패 → KR 폴백
  - 통합 템플릿의 `#`는 **숫자 자리가 아니라 옵션 텍스트 자리**라, 설령 조회에 성공했어도 `extractValues`가 KR 문장의 "15"를 집어 `grant: 15`라는 **조용히 틀린 결과**가 나온다. 옵션형 id 도입은 그 구조적 결함까지 없앤다
- **맵 재생성**(EN/KR stats 최신본으로 `scripts/build-pob-statmap.mjs` 재실행): poe1 14,969 → **17,684 ids**, poe2 8,086 → **8,127 ids**. 최신 stats API 대비 미매핑 poe1 2,733(그중 옵션형 1,603 · `mercenary` 그룹 534 통째로 누락) / poe2 41 → **양쪽 0건**
  - EN stats(`pathofexile.com/api/trade|trade2/data/stats`)는 **KR IP에서도 200으로 받힌다** — 스크립트 주석의 "VPN 필요"는 낡은 정보(거래소 *사이트*만 geo-redirect). 이번엔 VPN 없이 4종 다 받았다
- **`build-pob-statmap.mjs`에 레거시 병합 추가** — stats API는 "지금 검색 가능한" mod만 준다. 그대로 덮으면 삭제된 리그 mod(예: `While a Unique Enemy is in your Presence, …` 계열) 281건을 잃는데, 그런 아이템은 여전히 거래된다. 새 데이터에 없는 기존 항목은 유지하되 **옵션형으로 쪼개진 통합 id는 버린다**(위의 조용히 틀린 결과 방지). 결과적으로 유실 0
- 검증: 테스트 **318/318**(신규 3건 — 옵션형 id 변환·특성 할당 인챈트·통합 id 부재), 번들 맵으로 제보 아이템을 `buildPobText`에 통과시켜 `Added Small Passive Skills grant: 15% increased Armour (enchant)` + `missing: []` 확인, `npm run build` 성공(dist 2.9MB, poe1 맵 청크 1.50MB — PoB 버튼 클릭 시 lazy 로드라 초기 로드 무영향)
- ⚠ **기존 테스트 하나가 무의미해질 뻔했다**: `translateMod('enchant.stat_2954116742', '할당 골렘의 피')`가 `null`인지 보던 테스트는 재생성 후에도 통과하지만 이유가 "# 미치환"이 아니라 "id 자체가 사라짐"으로 바뀌었다 → 합성 맵으로 동작을 고정하고, 실데이터 케이스는 옵션형 블록으로 옮겼다
- **베이스 맵은 손대지 않았다** — `pobBaseMap*.json`은 별도 repo(poe-i18n 생성기) 입력이고 제보 아이템의 베이스는 정상 변환됐다

### 0.6.1 준비 — 조건 묶음 드래그 사용성 정비 + 칩 줄 접기 (2026-08-01, `d432957`)
- **0.6.0을 실사용한 사용자 제보**: 칩 드래그로 자리를 옮기기 어렵다. 원인이 셋이었다
  - ① 삽입이 항상 "대상 칩 앞" 고정 → 오른쪽으로 옮기려면 "옮길 자리의 **다음** 칩"을 노려야 해 결과가 어긋남 → **포인터가 칩의 어느 절반인지로 앞/뒤 결정**(선이 그어진 자리가 곧 놓이는 자리)
  - ② 조건 묶음 툴팁이 커서 놓을 자리를 가리고, 드래그 중엔 `mouseout`이 안 와 **굳어버림** → `dragstart`~`dragend` 동안 툴팁 억제(`tipSuppressed`)
  - ③ 좁은 칩 사이에서 삽입선만으로는 기준 칩이 안 읽힘 → **놓을 자리 프리뷰**(칩 줄 위 fixed 바, "〈옮기는 칩〉 → 〈어디로〉"). 이름은 textContent로만
- **드롭 강조를 라임(`--ba-drop: #d9f99d`)으로** — 패널이 보라 일색이라 보라 강조가 배경에 묻힌다는 제보. 자수정 바이올렛의 보색이면서 앰버(별)·골드(화폐)·로즈(위험)·시안(공유)과 의미가 겹치지 않는 유일한 빈자리. 삽입선도 2→3px
- **칩 줄 접기**(`uiSetsCollapsed`) — 묶음이 늘면 상단 최대 3줄을 점유해 목록을 잠식. 접어도 **라벨과 개수 배지는 남긴다**(사라지면 "클릭 1회로 조건 얹기"가 잊힌다). 폴더 접기와 같은 언어(회전 셰브론+배지). 투어 중에는 자동으로 펼쳤다 끝나면 복원
- ⚠ **하네스가 잡은 버그**: `wasCollapsed`가 이미 *패널* 접힘 상태로 쓰여 이름 충돌 → 패널 전체가 안 뜨는 SyntaxError. **테스트도 빌드도 못 잡았고** 하네스 로드에서만 드러났다 → `setsWasCollapsed`로 분리
- 검증: 테스트 315/315, 하네스에서 방향 판정·툴팁 억제·프리뷰 5개 상태·접기(71px→32px)·키보드 토글·색상 최종값 확인. **재로드 후 접힘 복원은 하네스가 매 로드 목 스토리지를 새로 시드해 확인 못 함 — 실제 확장에서 확인 필요**

### 기본 화폐 가격에도 신성한 오브 환산 칩 (2026-08-01, `667f646`)
- **발단(사용자 제보)**: 한 목록에 "350 카오스"와 "2 신성한"이 섞이면, 신성한 쪽엔 카오스 환산 칩이 붙지만 카오스 쪽엔 붙을 게 없어(이미 기본 화폐) 큰 카오스 숫자와 작은 신성한 숫자를 머릿속으로 나눠야 했다
- `currencyRates.js`: `divineFromPrice(price, rateData, game)` 신규 — `baseFromPrice`의 **반대 방향**(기본 화폐 → 신성한 오브). poe1 `chaos_per_divine`, poe2 `exalted_per_divine` 사용
- `content-main.js`: 칩에 `data-kind`(`base`|`divine`) 도입, `chipKindOf()`로 아이콘·라벨·폴백 텍스트 분기. static API에서 `divine` 아이콘도 함께 로드(`divIcon`)
- **임계값 `MIN_DIVINE_CHIP = 0.5`** — 20카오스(=0.06신성한)처럼 잔 가격에 "≈ 0.1 신성한"을 붙이면 정보가 아니라 소음이다. 비교가 필요한 큰 가격에서만 붙인다
- **"섞였을 때만" 조건은 일부러 넣지 않았다** — 무한 스크롤 부분 로드에서 섞임 판정이 흔들려 칩이 붙었다 사라지고, 섞이지 않아도 큰 카오스 가격의 신성한 환산은 그 자체로 유용하다. 원하면 조건 추가 가능
- 검증: 테스트 315/315(신규 4건), 거래소 static API 실측으로 `divine` id·한글명·이미지 존재 확인(poe1 `trade`·poe2 `trade2` 양쪽, Currency 103종). 라이브 칩 렌더는 거래소 페이지에서만 확인 가능 — **사용자 확인 필요**

### 조건 묶음 칩 — 드래그 재배치 + 상시 삭제 버튼 (2026-08-01, `d0db669` develop push 완료)
- **편집 모드(연필 토글 + 앞/뒤 화살표) 제거**. 드래그와 상시 `×`가 같은 일을 하게 되어 경로가 둘로 갈렸다
- 칩 자체가 드래그 핸들(칩이 작아 별도 그립을 넣으면 이름이 더 잘린다). 클릭=조건 얹기와는 dragstart/click으로 갈려 충돌 없음
- 드롭: 다른 칩 위 → 그 칩 **앞**, 칩 줄 빈 공간 → **맨 뒤**. 삽입 위치는 세로 보라선(왼쪽/오른쪽)으로 표시
- `store.js`: `moveConditionSetBefore(id, beforeId)` 신규(order 중간값 삽입 — 북마크 재정렬과 같은 방식), `removeConditionSet`이 **삭제 레코드 반환**, `restoreConditionSet` 신규. 인접 스왑 `moveConditionSet`은 키보드용으로 유지
- **다른 game 스코프 칩 위 드롭은 무시** — poe1/poe2는 스탯 id 체계가 달라 섞이면 검색이 깨진다
- 삭제는 확인 없이 즉시 + **실행취소 토스트**(6초). 원 설계가 "오클릭 방지"로 삭제를 숨겨뒀던 것을 상시 노출로 바꾸는 대신 둔 안전장치 — 확인 다이얼로그는 매번 마찰이지만 실행취소는 실수했을 때만 비용이 든다
- `toast(msg, action)` 확장 — 액션 버튼은 DOM API로 생성(묶음 이름이 들어가므로 innerHTML 금지)

### 조건 칩 클릭으로 능력치 추가 + 빈 폴더 표시 (2026-07-27)

**① 조건 칩 클릭 → 그 검색의 능력치만 지금 검색에 추가** (사용자 제안)
조건 묶음(칩 줄)은 "등록 → 이름 → 클릭" 3단계라 자주 쓰는 소수에만 맞는다. 북마크·히스토리 카드의 **조건 칩을 직접 클릭**하면 등록 없이 그 능력치를 바로 얹는다 — 사용자 계정의 raw query 보유 레코드 68개가 즉시 재료가 된다.

- **매번 레코드의 원본 query를 새로 읽는다** → 저장 스냅샷이 아니라서 "옛 묶음엔 그룹이 없다" 같은 마이그레이션 문제가 원천적으로 없다
- `applyAndGo()`로 실행 경로를 공통화(칩 줄·조건 칩이 같은 병합·POST·토스트·연타 차단을 공유)
- raw query가 없거나 능력치가 0개인 레코드는 클릭 불가(클래스 미부여)

**② 폴더 추가가 안 되던 문제** (사용자 제보)
`renderList`가 **빈 폴더를 전부 건너뛰고 있었다**(`if (!items.length && !(isCurrent && g.id === null)) continue`). 새로 만든 폴더는 당연히 비어 있으므로 **만들어도 화면에 안 나타나고**, 드래그해 넣을 대상조차 없어 폴더 기능을 시작할 수가 없었다. 저장은 정상이었고 렌더만의 문제.
- 현재 리그 섹션은 **빈 폴더도 표시**(드롭 타깃 "여기로 드래그"까지). 현재가 아닌 리그 섹션은 기존대로 숨김 — 조작 대상이 아니고 목록만 길어진다

**증상**: '숫자(count)' 그룹으로 나눠 만든 검색을 조건 묶음으로 등록하면 그룹이 저장되지 않는다.

**심각도가 보이는 것보다 높다 — 검색 의미가 바뀐다**: `count` 그룹은 "이 중 N개만 만족하면 됨"이다. 평탄화해 `and` 하나로 합치면 **전부 만족해야 하는** 완전히 다른(훨씬 좁은) 검색이 된다. 단순 누락이 아니라 조용한 오작동.

- `conditionSet.js` — `extractConditionSet`이 `groups: [{type, value, filters}]`를 함께 반환(그룹 타입 + 그룹 값 `숫자 ≥N` + `weight` 값까지 보존). 평탄 `stats`는 칩 개수 표시·하위호환용으로 유지
- `mergeConditionSet` 병합 규칙을 그룹 타입별로 분기:
  - `and` → 현재 검색의 `and` 그룹에 얹기(중복 id는 갱신). "전부 만족"이라 합쳐도 의미가 같다
  - `count`·`weight` 등 → **통째로 새 그룹으로 추가**. 그룹 자체가 하나의 조건이라 합치면 깨진다
- `store.js` — `addConditionSet`이 `groups`를 실제로 보관(안 그러면 추출해도 저장 단계에서 버려짐)
- 하위호환: `groups` 없는 기존 묶음은 `stats`를 `and` 그룹 하나로 취급

**검증**: 테스트 **273/273**. 스크린샷 시나리오(숫자≥1 그룹 + 숫자≥2 그룹)를 픽스처로 고정 — 그룹 2개가 `and`로 합쳐지지 않고 각자 `value.min`까지 유지되는지, 현재 검색의 기존 그룹은 안 건드리는지 확인.
**라이브 검증 (2026-07-27)**: 그룹 나뉜 북마크("목걸이 - 초반")를 새로 등록 → 얹기 → 필터 UI에 `숫자 (1)`·`숫자 (2)` 그룹이 각자 값과 소속 조건까지 그대로 재현됨(스크린샷 확인).

**라이브에서 이어서 발견 — 같은 그룹 중복 추가**: 이미 그 그룹을 가진 검색에 얹으면 동일한 `숫자 1` 그룹이 두 개가 됐다. `and`는 stat id로 중복을 걸렀지만 `count`·`weight`는 무조건 append했기 때문. `groupKey()`(타입 + 그룹 값 + 조건 집합, 순서 무관)로 동일 그룹이면 건너뛴다. 같은 묶음을 두 번 얹어도 그룹이 안 늘어난다. 비활성 그룹과는 비교하지 않음(검색에 적용 안 되므로).
