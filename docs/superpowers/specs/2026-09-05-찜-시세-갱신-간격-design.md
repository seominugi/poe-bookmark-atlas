# ④-b 찜 시세 갱신 간격(자동 주기) — 쿨다운·백오프 설계

> ## 결론 (사용자 결정 2026-09-05)
>
> **자동 주기는 넣지 않는다.** 아래 「대안」 절의 *"찜 N개를 확인할까요?"* 권유를 채택해 구현했다.
> 문서 나머지는 **그 판단의 근거와, 나중에 자동 주기가 다시 거론될 때 다시 파지 않기 위한 기록**이다.
>
> 구현된 것: `watchNudge()`(`src/lib/watchRefresh.js`) + 찜 섹션의 `.ba-wnudge` 배너.
> 오래된 찜이 **둘 이상**이면 뜨고, `지금 확인`은 기존 일괄 순회를 그대로 돌리며, `✕`는 **24시간 스누즈**다.

## 왜 이 문서가 있는가

제보(2026-09-04)의 넷째 항목이다. 나는 **받지 않기를 권했고**, 그 근거를 말한 뒤
*"그래도 넣자고 하시면 쿨다운·백오프 설계부터 다시 짜겠습니다"* 라고 적었다. 이 문서가 그 설계다.

**이건 구현 계획이 아니라 판단 자료다.** 아래를 읽고 넣을지 말지를 정하면 된다.
④-a(버튼 눌러서 일괄 조회)는 이미 만들었고 `develop` 에 있다 — 이 문서는 그 위에 **자동 주기**를
얹는 이야기다.

## 반대 근거는 그대로다 (먼저 읽을 것)

프로젝트 `CLAUDE.md` 「기능 수용 기준」의 **백그라운드 상시 동작** 항목에 정면으로 걸린다.

| 걸리는 것 | 왜 |
|---|---|
| **조용히 죽는 실패** | 지금 모든 기능은 사용자가 눌러야 돌고, 안 되면 그 자리에서 보인다. 주기 갱신은 안 돌아도 화면에 아무 일이 없다. "안 와요"는 사용자 쪽에서 검증할 수 없는 제보라 지원 부담이 끝나지 않는다 |
| **남의 예산을 태운다** | `/api/trade/fetch` 의 IP 한도는 **100요청/300초**이고 이 예산을 **거래소 사이트 자신과 공유한다.** 우리가 몰래 쓰면 사용자의 검색이 막힌다. 429 정지는 **엔드포인트 단위**라 확장뿐 아니라 실제 거래소 검색까지 멈춘다 |
| **이미 거절한 것과 같은 모양** | 「북마크 신규 매물 알림」(2026-08-23)을 거절한 이유가 그대로 여기에도 있다. 그때 결론은 *"비싼 건 절반 만들어진 부분이 아니라, 백그라운드로 도는 것 자체"* 였다 |

**한 줄로**: 찜 상태를 알려주려고 거래소를 못 쓰게 만드는 건 앞뒤가 바뀐 것이다.

## 그럼에도 만든다면 — 설계

### 원칙 넷

1. **자동 실행은 '사용자가 보고 있을 때'만.** 서비스 워커 알람으로 백그라운드에서 도는 방식은 쓰지 않는다.
   거래소 탭이 **열려 있고 활성일 때만** 돈다. 그러면 실패가 화면에서 보이고, 사용자가 안 볼 때는 예산을 안 쓴다.
2. **예산 대신 잉여만 쓴다.** ④-a 의 `longWindowHeadroom` 을 그대로 쓰되, 자동 경로는 예약분을
   훨씬 크게 잡는다(`USER_RESERVE` 30 → 자동은 **60**). 남는 게 확실할 때만 한 건 보낸다.
3. **실패하면 스스로 물러난다.** 429 한 번이면 자동을 **그 세션 동안 끈다**(다음 페이지 로드까지).
   재시도로 정지를 늘리지 않는다.
4. **꺼져 있는 게 기본.** 설정에서 켠 사람에게만 돈다.

### 상태 기계

```
꺼짐 ──(설정에서 켬)──> 대기
대기 ──(간격 경과 + 탭 활성 + 잉여 충분)──> 한 건 조회 ──> 대기
대기 ──(탭 비활성)──> 멈춤(재개 시 대기)
한 건 조회 ──(429)──> 잠금(이 세션 동안 자동 중지) + 사용자에게 1회 알림
```

**한 번에 한 건만 본다.** ④-a 처럼 목록을 훑지 않는다 — 오래된 것 하나만 갱신하고 간격만큼 쉰다.
찜 20개에 5분 간격이면 한 바퀴에 100분이 걸리는데, **그게 의도다.** 빠르게 돌면 예산을 태운다.

### 간격 선택지

사용자에게 분 단위 자유 입력을 주지 않는다. 짧게 넣으면 그대로 사고가 된다.

| 선택지 | 한 건당 간격 | 찜 20개 한 바퀴 | 300초 창에서 쓰는 요청 |
|---|---|---|---|
| **끔** (기본) | — | — | 0 |
| 느리게 | 10분 | 200분 | 0.5 |
| 보통 | 5분 | 100분 | 1 |

**5분보다 짧은 선택지는 두지 않는다.** IP 창이 300초라, 그보다 촘촘하면 창마다 요청이 겹친다.

### 저장할 상태

| 키 | 뜻 |
|---|---|
| `uiWatchAutoInterval` | `0`(끔) \| `600000` \| `300000` |
| 찜 레코드의 기존 `checkedAt` | **다음 대상 고르기에 그대로 쓴다** — 가장 오래 안 본 것부터. 새 필드가 필요 없다 |

세션 안에서만 쓰는 것(자동 잠금 여부, 다음 시각)은 **저장하지 않는다.** 저장하면 그 상태가
굳어서 "왜 안 도는지 모르겠다"가 된다.

### 어디에 사는가

`src/content/panel/renderList.js` 가 아니라 **`src/content/content-main.js` 쪽 타이머**다 —
패널이 접혀 있어도 탭이 열려 있으면 돌아야 하기 때문이다. 다만 `watchGate` 를 공유해야 하므로
게이트를 `src/lib/` 로 올려야 한다(지금은 `renderList.js` 모듈 스코프).

`document.visibilityState === 'visible'` 로만 돈다. `chrome.alarms` 는 **쓰지 않는다** —
그게 곧 백그라운드 상시 동작이다.

### 새 권한

**없다.** `alarms` 를 안 쓰므로 매니페스트가 그대로고, 기존 사용자 재승인도 없다.
(이 점은 「기능 수용 기준」의 네 번째 항목은 안 건드린다는 뜻이다. 나머지 셋은 여전히 걸린다.)

## 만들기 전에 재야 할 것 (§26)

설계값 중 **측정으로 확인 안 된 것**이 둘이다. 구현에 들어가면 먼저 잰다.

1. **거래소 사이트가 평소 `/fetch` 를 얼마나 쓰는가.** `USER_RESERVE` 를 60으로 잡은 건
   추정이다. 실제로 검색 한 번이 몇 요청인지 재고 정해야 한다.
2. **`x-rate-limit-*-state` 가 우리 요청만 세는가, 탭 전체를 세는가.** 계정·IP 단위라
   탭 전체일 것으로 보이지만 **확인 안 했다.** 만약 우리 것만 센다면 잉여 판정이 통째로 무의미해지고,
   이 설계의 안전장치가 사라진다 — **이게 착수 전 첫 번째 확인 항목이다.**

## 대안 — 채택하고 구현한 것

찜이 있고 마지막 확인이 오래됐으면 **"찜 N개를 확인한 지 오래됐어요 · [지금 확인]"** 을 띄운다.
누르면 ④-a 순회가 그대로 돈다.

- 사용자가 누른다 → **조용히 죽는 실패가 없다**
- 예산은 ④-a 의 규칙(헤더 잔량 판정·700ms 간격·중단)이 이미 지킨다
- 새 권한 0, 새 타이머 0, 새로 만든 것은 판정 함수 하나와 배너 하나

자동 주기의 값어치 대부분(**잊지 않고 갱신됨**)을 가져오면서 「기능 수용 기준」에 걸리지 않는다.

### 구현한 규칙

| | 값 | 왜 |
|---|---|---|
| '오래됨' 기준 | **1시간** (`WATCH_STALE_MS`) | 매물은 분~시간 단위로 팔린다. 하루는 너무 길고 몇 분은 같은 세션에서 계속 뜬다. **측정값이 아니라 고른 값이다** |
| 띄우는 최소 개수 | **2개** | 하나뿐이면 행의 개별 '확인' 으로 충분하다. 한 건 때문에 배너를 띄우면 배너가 목록보다 커 보인다 |
| 확인한 적 없음 | **오래된 것으로 센다** | 그게 가장 모르는 상태다 |
| `✕` | **24시간 스누즈** (`NUDGE_SNOOZE_MS`) | **영구 숨김은 두지 않는다** — 한 번 잘못 누르면 기능이 영영 사라지는데 사용자는 되돌릴 방법을 못 찾는다 |

### 배선에서 조심한 것

- **`지금 확인` 은 배너를 먼저 지우고 순회를 시작한다.** 안 지우면 도는 중에 다시 눌러 **'중단'** 이
  된다 — 누른 것과 정반대 결과다. 진행 표시는 섹션 머리의 '전체 확인' 버튼이 이미 나르므로 거기 위임한다.
- **도는 중에는 배너를 그리지 않는다.** 지금 갱신되고 있는데 "오래됐다"고 말하면 어긋난다.
- **`✕` 는 재렌더하지 않는다.** 배너 하나 지우려고 목록 전체를 다시 그리면 스크롤이 튄다.
